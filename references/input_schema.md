# build_report.py 输入 JSON 字段说明

顶层是一个对象，字段如下。所有金额传**数字**（不带 ¥、不带引号），脚本负责货币格式与合计公式。

| 字段 | 类型 | 说明 |
|---|---|---|
| `month` | string | 月份标签，如 `"2026-05"`，用于标题和文件名 |
| `detail` | array | 消费明细，每行 `[日期, 交易对方, 商品/说明, 大类, 金额, 来源, 备注]`。**大类**必须是六类之一：固定支出 / 日常生活 / 健康医疗 / 孝亲 / 个人生活 / 社交。来源填 微信 / 支付宝 / 信用卡 等 |
| `receivables` | array | 代垫·待回收（应收，不计消费），每行 `[项目, 金额, 状态/说明]` |
| `excluded` | array | 不计入消费的支出，每行 `[项目, 金额, 原因]`。退款可拆两行（支出为正、退款为负） |
| `reconciliation` | array | 信用卡对账，每行 `[信用卡交易, 金额, 对应来源, 对账状态]` |
| `summary_notes` | array[string] | 汇总页底部口径说明，逐条写清本月判断。首行通常是 `"口径说明："` |
| `optimize_headline` | string | 可优化页顶部一句话结论，如"明确可省：¥816 / 年（…）" |
| `optimize_actionable` | array | 确定可行动的省钱项，每行 `[项目, 现状, 年化支出(数字), 潜在可省/年(字符串), 建议]` |
| `optimize_toconfirm` | array | 待确认项，每行 `[待核查项, 年化支出(数字), 需要的信息, 若成立·可省/年]` |
| `optimize_notes` | array[string] | 可优化页底部说明 |

## 汇总页如何算

汇总页的六类金额用 `SUMIF` 从 `消费明细` 页按"大类"列自动汇总，占比 = 该类 / 合计。所以：

- `detail` 里每行的大类拼写必须与六类**完全一致**，否则漏统计。
- 金额随明细联动，改明细数字后重算即更新。
- `receivables` / `excluded` 不进消费合计。

## 空字段

某个数组本月没有内容就传 `[]`（如某月没有代垫，`receivables: []`）。脚本会跳过对应小节的行、保留标题结构。
